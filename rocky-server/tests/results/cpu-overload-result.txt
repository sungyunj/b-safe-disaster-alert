B-SAFE CPU 과부하 테스트 결과

테스트 방식
- 100 VU 고정 부하
- 총 실행 시간: 3분
- 테스트 시작 약 1분 후 VM-A에 CPU 100% 과부하 적용
- CPU 과부하 유지 시간: 약 1분
- 대상: http://20.249.156.9/alerts

결과
- 총 요청 수: 13,233회
- 성공 요청 수: 12,969회
- 실패 요청 수: 264회
- HTTP 실패율: 1.99%
- 검사 성공률: 98.00%
- 검사 실패: 528회
- VM-A 응답 수: 6,457회
- VM-B 응답 수: 6,512회
- 평균 응답시간: 188.98ms
- 중앙값 응답시간: 20.95ms
- P90 응답시간: 32.64ms
- P95 응답시간: 1.03초
- 최대 응답시간: 10초
- 완료 iteration: 13,233회
- 중단 iteration: 0회
- 평균 iteration 시간: 1.36초
- 최대 iteration 시간: 11초

임계값 결과
- http_req_failed < 5%: 통과
- http_req_duration P95 < 2초: 통과
- checks > 95%: 통과

특이사항
- VM-A에 CPU 100% 과부하를 적용한 구간에서 응답시간이 크게 증가함
- 정상 구간 대비 평균 응답시간이 약 20ms대에서 188.98ms로 증가함
- P95 응답시간이 1.03초까지 증가함
- 일부 요청은 최대 10초까지 지연됨
- 총 264건의 요청 실패가 발생함
- VM-A와 VM-B 응답 수가 거의 동일하여 Load Balancer가 두 서버에 계속 요청을 분산한 것으로 확인됨
- CPU 과부하 상태에서도 VM-A의 Health Probe가 계속 성공하여 VM-A가 백엔드 풀에서 완전히 제외되지는 않은 것으로 판단됨
- CPU 과부하는 서버를 완전히 중단시키기보다는 응답 지연과 일부 timeout을 발생시키는 형태로 나타남

최종 결론
VM-A에 CPU 100% 과부하를 약 1분간 적용한 결과, 평균 응답시간과 P95 응답시간이 크게 증가했고 총 264건의 요청 실패가 발생하였다. 그러나 VM-A가 완전히 비정상 상태로 판정되지는 않아 VM-A와 VM-B가 계속 함께 요청을 처리하였다.
